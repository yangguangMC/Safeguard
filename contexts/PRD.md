# SafeGuard 产品需求文档（PRD）

## 一、产品概述

**SafeGuard** 是一个面向高版本 Minecraft Java Edition 的 Fabric 客户端模组，专为原版生存玩法设计。 其核心使命是：
**通过主动接管或被动提醒的方式，保护玩家免受游戏内各种危险情境的伤害**
——包括但不限于摔落、岩浆、窒息、怪物偷袭、玩家偷袭（PVP）等。

与市面上其他安全/辅助类模组不同，SafeGuard 聚焦于 **原版生存及其衍生场景**， 不做玩法层面的改动，不引入新物品、新机制或新维度，而是纯粹作为
**客户端侧的安全辅助工具**存在。 所有检测与保护动作均在客户端本地完成，不依赖服务端支持，适用于单机、局域网和各类服务器环境。

## 二、目标用户

| 用户类型           | 描述                                                               |
|--------------------|--------------------------------------------------------------------|
| **原版生存玩家**   | 在生存模式中探索、建造、冒险，希望减少因疏忽或意外导致的死亡损失   |
| **硬核模式玩家**   | 在 Hardcore 模式下不容许任何死亡，需要额外的安全预警和防护         |
| **PVP 玩家**       | 在 PVP 场景中需要战斗辅助提醒（如对手逼近、低血量警告等）          |
| **服务器玩家**     | 在各类服务器上游玩，希望获得客户端侧的安全增强，不受服务端规则限制 |
| **模组整合包玩家** | 在复杂模组环境中仍希望保留原版生存的核心安全辅助能力               |

## 三、核心功能列表

### 3.1 环境危险类保护

| 功能         | 描述                                                                                   | 保护动作                                                                     |
|--------------|----------------------------------------------------------------------------------------|------------------------------------------------------------------------------|
| **摔落保护** | 检测玩家向下挖掘时下方是否存在不安全因素；与目标摔落区域之间是否高于致命摔落伤害的高度 | 主动：水桶放置（若手持）；被动：HUD 警告、音效提示                           |
| **窒息检测** | 检测玩家头部是否位于固体方块内并提示上方窒息重力影响方块的数量；提示最短破解路径       | 主动：自动挖掘窒息方块（若可破坏）和放置火把（若可用）；被动：警告提示       |
| **火焰检测** | 检测玩家是否身上着火，还将持续几秒；                                                   | 被动：警告提示；提示玩家解决方案如最近可灭火物的方向、背包内可用的物品、药水 |

### 3.2 战斗类保护

| 功能           | 描述                                                                                                             | 保护动作                                                               |
|----------------|------------------------------------------------------------------------------------------------------------------|------------------------------------------------------------------------|
| **苦力怕预警** | 检测苦力怕接近和引燃状态                                                                                         | 主动：操作模拟玩家远离，暂停与退出；被动：HUD 和声音紧急警告、方向指示 |
| **偷袭检测**   | 检测是否有其他玩家和生物：快速靠近；潜行/隐身/躲藏一段时间；长时间处在玩家背后一定距离处；手持近战或远程武器瞄准 | 被动：屏幕边缘提示、方向箭头、高亮提示                                 |
| **弹射物预警** | 检测是否有飞行的弹射物朝向玩家并向其靠近                                                                         | 被动：警告提示方向和发射者、预期伤害（可选）、高亮提示                 |

### 3.3 状态与资源保护

| 功能             | 描述                                 | 保护动作                                   |
|------------------|--------------------------------------|--------------------------------------------|
| **受伤检测**     | 检测收到伤害的情况，用于 AFK 时      | 主动：暂停与退出                           |
| **饥饿监测**     | 检测玩家饱和度与饥饿值（和生命值）   | 被动：低饥饿值时屏幕提示，提示最优食物方案 |
| **低血量警告**   | 血量低于阈值或对手斩杀线时触发警告   | 被动：屏幕提示                             |
| **装备耐久警告** | 盔甲/手持物耐久度过低时提醒          | 被动：图标提示                             |
| **状态效果监测** | 显示当前即将结束的药水效果及剩余时间 | 被动：HUD 显示                             |
| **方块光照监测** | 检测当前光照是否会导致怪物生成       | 被动：提示最优插火把位置                   |

### 3.4 配置与管理

| 功能               | 描述                                                     |
|--------------------|----------------------------------------------------------|
| **功能开关**       | 每个检测功能独立开关                                     |
| **显示方式配置**   | 警告的显示方式可选：屏幕文字、HUD 图标、音效、边缘闪烁等 |
| **阈值调节**       | 各检测项的触发阈值可调（如低血量百分比、检测半径等）     |
| **配置界面**       | 游戏内可视化配置界面（集成 Mod Menu）                    |
| **配置文件持久化** | 所有配置保存至本地文件，跨游戏会话生效                   |

## 五、界面设计要求

### 5.1 配置界面

- 除使用指令外，集成 **Mod Menu**，在模组列表页提供“配置”入口
- 使用 **YetAnotherConfigLib** 构建可视化配置界面
- 配置项按功能分类（环境检测、生物检测、状态监测、显示设置）
- 每个功能项带开关 toggle、详细配置用滑块/输入框
- 显示方式配置：多个开关（文字、图标、音效、高亮等）

### 5.2 游戏内 HUD

- **轻量设计**：不遮挡核心游戏视野
- 警告信息显示在屏幕边缘或角落
- 使用图标 + 简短文字的组合
- 不同危险等级使用不同颜色（黄色=注意、红色=危险）
- 支持透明度调节

### 5.3 交互反馈

- 警告出现时伴有清晰的视觉和/或音效反馈
- 同一类型的警告有冷却时间，避免刷屏

## 七、代码风格与架构模式

### 7.1 架构模式

采用 **模块化分层架构**：

```
┌──────────────────────────────────────┐
│           配置层 (Config)            │
│    (Cloth Config + Mod Menu)         │
├──────────────────────────────────────┤
│          管理层 (Manager)            │
│ 各功能模块的注册、启停、生命周期管理 │
├──────────────────────────────────────┤
│         检测层 (Detection)           │
│各检测功能的实现（事件监听、定时扫描）│
├──────────────────────────────────────┤
│         动作层 (Action)              │
│  保护动作的实现（警告、主动干预）    │
└──────────────────────────────────────┘
```

### 7.2 代码规范

- 遵循 Java 标准命名规范（CamelCase、PascalCase）
- 包名：`top.yangguangmc.safeguard.<module>` 格式

### 7.3 设计模式

- **上下文对象模式**：核心管理器（ProtectionManager、ConfigManager）
- **观察者模式**：事件监听与回调
- **策略模式**：不同保护动作的实现（警告策略、主动干预策略）

## 八、限制条件与边界场景

| 类别                   | 说明                                                     |
|------------------------|----------------------------------------------------------|
| **客户端专用**         | 所有功能仅依赖于客户端数据，不向服务端单独发送任何数据包 |
| **服务端兼容性**       | 不修改服务端行为，兼容所有原版及模组服务端               |
| **不干扰服务端反作弊** | 不发送异常数据包，不修改核心数据                         |
| **性能影响**           | 检测逻辑需轻量，避免高频扫描导致掉帧                     |
| **模组冲突**           | 避免与同类辅助模组的功能重复和冲突                       |
| **多人游戏公平性**     | 仅提供信息辅助，不赋予明显严重作弊的能力（如飞行、穿墙） |
| **单机/局域网**        | 完全支持，不依赖外部服务                                 |
| **配置重置**           | 提供恢复默认配置的选项                                   |
| **错误处理**           | 单个检测模块崩溃不应影响整体模组运行                     |
